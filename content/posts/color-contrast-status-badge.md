## 문제

포트폴리오 디자인 토큰을 정리하면서 `Badge` 컴포넌트를 만들었습니다. 흔히 쓰는 방식대로 상태색을 10% 투명도로 깐 배경 위에 같은 계열의 텍스트를 올렸습니다. 보기에는 자연스러웠지만, 대비를 계산해 보니 일반 텍스트 기준인 4.5:1에 못 미치는 조합이 있었습니다.

| 상태        | 대비 |
| ----------- | ---: |
| primary     | 4.49 |
| success     | 4.50 |
| warning     | 4.50 |
| destructive | 4.13 |

기준은 WCAG 2.1의 일반 텍스트 4.5:1입니다. destructive는 확실히 미달이고, 나머지도 기준선 언저리라 여유가 없었습니다.

## 원인

텍스트 색만 보면 통과하는 색이었습니다. 문제는 **배경이 바뀐다는 점**이었습니다. 흰 배경 위에서는 통과하던 텍스트 색이, 같은 색을 섞은 tint 배경 위에서는 배경이 어두워진 만큼 대비가 줄어듭니다.

투명도를 4%까지 낮춰도 destructive는 `#FAFAFA` 위에서 4.37이라 통과하지 못했습니다. 투명도를 조정하는 방식으로는 풀리지 않았습니다.

## 해결

tinted 배경을 포기하고 다음 구성으로 바꿨습니다.

- 배경은 흰 `surface`
- 테두리는 `border` (장식용)
- 텍스트는 상태 텍스트 토큰
- 색 외의 단서로 점(dot)을 함께 표시

흰 surface 위의 텍스트 대비는 가장 낮은 destructive가 4.83이고, 나머지는 그 이상입니다.

앞선 단계에서 한 가지 더 정리한 것이 있습니다. Success와 Warning 원색(`#16A34A`, `#D97706`)은 흰 배경에서도 3.30, 3.19로 텍스트에 쓸 수 없었습니다. 그래서 아이콘·점에 쓰는 원색과 텍스트에 쓰는 토큰을 분리했습니다.

| 토큰             | 값        | 흰 배경 대비 | 용도       |
| ---------------- | --------- | -----------: | ---------- |
| `--success`      | `#16A34A` |         3.30 | 아이콘, 점 |
| `--success-text` | `#15803D` |         5.02 | 텍스트     |
| `--warning`      | `#D97706` |         3.19 | 아이콘, 점 |
| `--warning-text` | `#B45309` |         5.02 | 텍스트     |

## 선택 근거와 trade-off

- **tint 배경을 유지하면서 텍스트를 더 진하게** 만드는 방법도 있었습니다. 하지만 기존 `*-text` 토큰보다 더 진한 색이 상태마다 하나씩 더 필요해 토큰이 늘어납니다.
- **흰 surface + 점**은 새 색 토큰이 필요 없고, 대비가 배경에 상관없이 보장됩니다.
- 대신 tint보다 시각적 강도가 약합니다. 상태를 한눈에 구분하는 힘은 점과 텍스트 라벨이 대신합니다.
- 색만으로 상태를 전달하지 않는다는 접근성 원칙에도 맞습니다.

## 결과

- 모든 상태 Badge 텍스트가 흰 surface 위에서 4.83 이상입니다.
- Badge를 위한 새 색 토큰은 추가하지 않았고, 상태 텍스트는 `*-text` 토큰만 쓰는 규칙으로 정리됐습니다.
- 이 결정은 저장소의 `docs/DECISIONS.md`(D-015)에 기록했습니다.

디자인 단계에서 색을 정할 때 텍스트 색 한 가지만 검사하지 말고, **그 텍스트가 놓일 실제 배경과의 조합**으로 검사해야 한다는 점을 이번에 확인했습니다.
